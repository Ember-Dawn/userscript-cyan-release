# ChatGPT 朗读增强助手

文件：`chatgpt-read-aloud-enhancer.user.js`

该脚本增强 ChatGPT 网页版的官方“朗读”功能，不自行生成语音，也不替换 ChatGPT 的声音。它在每条助手回答的一级操作栏末尾增加快捷按钮，并在官方音频真正开始播放后显示紧凑悬浮播放器。

## 主要功能

- 一级“朗读 / 重播”快捷按钮；
- 播放、暂停、进度拖动和时间显示；
- 快退、快进，步长可选 3、5、10 秒，默认 3 秒；
- 播放速度可选 0.75×、1×、1.25×、1.5×、2×；
- 播放上一条或下一条当前可见的助手回答；
- 最小化、关闭和聊天切换状态清理；
- 将当前朗读音频在浏览器本地转换为 MP3 并保存。

## 播放器与快捷键

| 按键 | 功能 |
|---|---|
| `↑` | 播放上一条助手消息 |
| `↓` | 播放下一条助手消息 |
| `←` | 按当前跳转步长快退 |
| `→` | 按当前跳转步长快进 |
| `Space` | 播放或暂停 |
| `Esc` | 关闭播放器并暂停 |

焦点位于输入框、文本域、下拉框或可编辑区域时，脚本不会接管这些快捷键。

## 上一条与下一条

消息列表只在用户点击切换按钮或按下 `↑` / `↓` 时即时扫描，不会持续高频遍历页面。脚本只处理当前页面中可见、带有有效回复操作栏的助手回答。

- 到达第一条或最后一条时停止，不循环；
- 新增消息后会在下一次切换时重新读取；
- 重新回答或切换回答版本后，会按当前可见消息重新计算；
- 切换聊天时会停止并解绑旧聊天中的音频，隐藏播放器并重置消息上下文。

## MP3 下载

点击播放器顶部的下载按钮后，脚本会在当前浏览器中完成一次性处理：

1. 读取 ChatGPT 当前官方朗读音频；
2. 使用 Web Audio API 解码；
3. 在当前标签页本地转换为单声道、96 kbps MP3；
4. 通过普通浏览器下载方式保存，不弹出文件路径选择器。

转换期间，下载按钮使用独立的纯 CSS 圆环持续旋转，不与编码进度绑定，也不更新百分比或中间文字。转换成功后短暂显示勾号，失败时显示感叹号并保存最近一次脱敏诊断日志。

音频不会上传到第三方服务器。MP3 编码优先在运行时创建的内联 Web Worker 中执行，使播放器动画和页面操作保持流畅；若浏览器阻止 Worker，脚本会自动回退到主线程编码。

MP3 编码通过 userscript 头部的 `@require` 加载 `lamejs-fixed 1.2.2`。脚本会直接读取 Tampermonkey 与 `@require` 共享作用域中的编码器对象，不再仅依赖 `window.lamejs`。该依赖采用 LGPL-3.0 许可：

- 项目：`https://github.com/zhuker/lamejs`
- 加载地址：`https://cdn.jsdelivr.net/npm/lamejs-fixed@1.2.2/lame.min.js`

### 诊断日志

MP3 下载失败时，脚本只保留最近一次脱敏日志。通过 播放器日志按钮中的“导出最近一次 MP3 诊断日志”导出 JSON。日志不包含对话正文、音频内容或带查询参数的完整音频地址。

## 数据与隐私

- 跳转秒数、播放速度和播放器折叠状态仅保存在浏览器 `localStorage`；
- 脚本不保存 ChatGPT 对话正文；
- 脚本不上传朗读音频；
- MP3 解码、编码和保存均在当前浏览器中完成。

## 已知限制

- ChatGPT 页面结构或官方朗读实现变化后，DOM 选择器可能需要更新；
- 官方流式音频刚开始播放时，总时长可能暂时不可用，进度条会在时长可用后恢复；
- 音频源无法被浏览器读取、源格式无法解码或 MP3 编码依赖加载失败时，下载会失败；
- 长音频转换会短暂占用 CPU 和内存。

## 3.5.0 播放器设置与转码行为

- “跳转”和“速度”改为播放器内部的深色自定义菜单，不再使用系统原生白色下拉层；
- 两个设置框略微缩短，且不显示额外的下拉箭头符号；
- 自定义菜单支持当前选中状态、点击外部关闭和 `Esc` 关闭；
- MP3 的单声道混合与编码优先放入运行时内联 Worker，避免阻塞下载图标动画和播放器操作；
- Worker 无法启动或加载编码器时，自动回退到原有主线程编码，不影响下载可用性；
- 转换过程继续只显示旋转图标，成功后只短暂显示勾号，不显示中间状态文字。


## 3.5.1 下载忙碌状态优化

- 下载中的旋转状态改为独立纯 CSS 圆环，不再旋转或反复更新 SVG；
- Worker 不再发送逐块进度消息，主线程不再更新百分比、Tooltip 或无障碍标签；
- 单声道混合和 MP3 编码继续在 Worker 中完成，声道数组通过 transferable 传递；
- 下载流程开始后先让浏览器完成一帧渲染，再读取、解码和编码音频；
- 仅在开始、成功和失败时更新下载按钮状态。
