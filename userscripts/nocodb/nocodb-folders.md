# NocoDB 文件夹脚本

`nocodb-folders.user.js` 为 NocoDB 左侧表格列表增加文件夹、嵌套文件夹、排序、搜索、拖放和 WebDAV 多端同步能力。

本文档对应脚本版本 **11.1.1**。

## 1. 功能概览

- 创建、重命名、删除和着色文件夹；
- 创建嵌套子文件夹；
- 将表格或文件夹拖入其他文件夹；
- 将表格或文件夹拖回根目录；
- 按中文和数字规则自动排序根目录、文件夹及表格；
- 搜索表格并保留其完整父文件夹路径；
- 导入和导出本地 JSON 备份；
- 使用紧凑的“加号 + Folder”按钮创建文件夹，在保持文字辨识度的同时减少左侧工具栏占用；
- 通过 WebDAV 自动同步文件夹结构；
- 首次连接时根据本机与云端数据状态安全建立同步基线；
- 设置面板实时显示保存、检查、拉取、上传、成功、失败和冲突状态；
- 使用 ETag / 条件请求防止旧设备静默覆盖新数据；
- 每日创建一个远端快照，并自动清理较旧快照；
- 发生冲突时保留安全副本并由用户决定采用哪一版。

## 2. 哪些数据会同步

WebDAV 只同步真正需要跨设备一致的内容：

- 每个 NocoDB Base 的文件夹列表；
- 文件夹名称、层级和颜色；
- 表格与文件夹之间的对应关系。

以下内容只保存在当前浏览器，不跨设备同步：

- 文件夹展开或折叠状态；
- 文件夹间距和缩进；
- 表格水平偏移；
- 双击延迟；
- WebDAV 地址、用户名和密码；
- 当前搜索词和其他临时界面状态。

这样可以避免 Windows Chrome 和 macOS Safari 因屏幕尺寸、布局偏好不同而互相覆盖界面设置。

## 3. 自动同步机制

### 3.1 首次启用与页面启动

仅打开 **Enable WebDAV** 开关不会立即联网。填写连接信息并点击 **Save and Check Now** 后，脚本才会保存配置、允许自动同步并建立当前 WebDAV 文件的同步基线。

首次建立基线时采用以下规则：

| 本机文件夹数据 | WebDAV 文件 | 行为 |
|---|---|---|
| 空 | 有数据 | 自动拉取云端结构 |
| 有数据 | 不存在或结构为空 | 自动上传本机结构并创建或更新云端文件 |
| 与云端完全一致 | 有数据 | 不覆盖任何一方，直接建立同步基线 |
| 有数据且与云端不同 | 有不同数据 | 暂停同步并要求用户选择采用云端或本机版本 |

最后一种情况不会自动合并、自动覆盖或简单拼接数组，因此不会因为首次在其他电脑安装而生成一套重复文件夹。脚本会保留两边原状，并尝试把本机结构写入 `backups/` 目录作为安全副本。

同步基线成功建立后，后续页面启动才会自动检查远端；如果用户修改了 WebDAV URL、用户名或密码，自动同步会再次暂停，直到重新点击 **Save and Check Now**。

### 3.2 本地修改

创建、移动、重命名、删除或着色文件夹后：

1. 立即写入 Tampermonkey 本地存储；
2. 标记存在待上传结构变更；
3. 等待 2 秒防抖；
4. 2 秒内的连续操作合并为一次上传；
5. 上传前检查远端版本；
6. 只有远端仍是本设备上次读取的版本时才覆盖主文件。

如果本地内容与已知远端内容完全相同，脚本会直接清除“待上传”状态，不发送重复的 `PUT`。

### 3.3 远端修改

脚本采用低开销检查策略：

- 切回 NocoDB 标签页或窗口获得焦点时检查；
- 页面从后台恢复为可见时检查；
- 页面保持可见时每 30 秒检查一次；
- 页面隐藏时停止周期检查。

检查时优先使用 `HEAD`；如果服务不支持或没有返回版本信息，则降级为 `PROPFIND Depth: 0`。正常情况下，只有检测到 ETag、修改时间或文件大小发生变化时，才下载完整 JSON。若服务完全不提供这些版本标识，脚本会在窗口聚焦或标签页恢复可见时读取正文，并在持续前台运行时最多每 5 分钟读取一次正文，用内容哈希判断变化。

## 4. 全量同步与备份

### 4.1 主同步文件

主文件采用完整 JSON 快照，并通过 `PUT` 覆盖同一个 WebDAV 文件。

这是“全量同步”，但不是“每次修改都新增一份全量备份”：

- 连续修改经过 2 秒防抖后只上传一次；
- 相同内容不会重复上传；
- 主文件只保留当前版本；
- JSON 通常很小，全量写入比操作日志或增量合并更简单可靠。

主文件中不会包含 WebDAV 用户名和密码。

### 4.2 每日快照

每次成功上传后，脚本会检查当天是否已有快照：

```text
<主文件所在目录>/backups/nocodb-folders-YYYY-MM-DD.json
```

规则：

- 每天最多创建一个；
- 使用 `If-None-Match: *`，多台设备不会反复覆盖同一天的快照；
- 默认保留约 14 天；
- 清理操作每天最多执行一次；
- WebDAV 不支持目录列举或删除时，主同步仍可继续，只是旧快照可能需要手动清理。

### 4.3 冲突安全副本

检测到冲突时，脚本会尝试创建：

```text
backups/nocodb-folders-conflict-local-<时间>-<设备>.json
```

如果用户选择“用本地版本覆盖云端”，脚本还会先尝试保存当前远端版本：

```text
backups/nocodb-folders-remote-before-overwrite-<时间>-<设备>.json
```

## 5. 冲突保护

### 5.1 首选机制：ETag + If-Match

成功读取远端文件后，脚本保存 WebDAV 返回的 ETag。上传时发送：

```http
If-Match: <上次读取的 ETag>
```

如果其他设备已经更新远端文件，服务器通常返回：

```text
412 Precondition Failed
```

脚本会停止上传，不会把旧数据静默覆盖到云端。

### 5.2 WebDAV 没有 ETag 时

脚本会先退化为比较：

- `Last-Modified`；
- 文件大小；
- 上传时的 `If-Unmodified-Since`。

若服务连这些版本标识也不提供，脚本会在上传前重新 `GET` 远端正文，并确认其内容哈希仍与本设备上次拉取的版本一致后再写入。这是尽力而为的保护，`GET` 与 `PUT` 之间仍存在极短的竞态窗口；只有标准 ETag 与 `If-Match` 能提供无竞态的条件写入。推荐使用能正确返回 ETag 并支持条件请求的 WebDAV 服务。

### 5.3 首次同步选择与普通冲突

点击工具栏中的同步图标，可以看到同步状态。

首次连接时，如果本机和 WebDAV 都有不同数据，会显示“首次同步需要选择”：

- **采用云端版本（替换本机结构）**：保留本机界面设置和有效折叠状态，采用云端文件夹结构；
- **上传本机版本（替换云端结构）**：先尝试备份远端，再上传本机结构；
- **导出本地安全副本**：下载 JSON 文件供人工检查；
- 关闭窗口：暂不处理，自动覆盖继续保持暂停。

正常运行中检测到并发修改时，可选择：

- **使用云端版本**：放弃当前本地待上传结构，拉取远端；
- **用本地版本覆盖云端**：先备份远端，再强制上传本地版本；
- **导出本地安全副本**：下载 JSON 文件供人工检查。

脚本不会自动进行字段级合并，因为“删除文件夹”“移动父文件夹”和“同时改变表格归属”等操作很难安全推断用户意图。

## 6. WebDAV 配置与状态反馈

在 NocoDB 左侧工具栏点击齿轮：

1. 打开 **Enable WebDAV**；
2. 填写完整的 JSON 文件 URL，而不是只填写目录；
3. 填写用户名和密码；
4. 点击 **Save and Check Now**。

打开开关只会显示配置字段，不会立即发送网络请求。只有点击保存检查按钮，或者之后在同步状态窗口中主动执行检查、拉取或上传，才会允许该端点进入自动同步。

示例：

```text
https://dav.example.com/nocodb/nocodb-folders.json
```

按钮会直接显示当前阶段：

- `Saving…`：保存本机连接配置；
- `Checking WebDAV…`：检查远端文件和版本标识；
- `Pulling from Cloud…`：拉取云端结构；
- `Uploading…`：上传本机结构；
- `Up to Date ✓`、`Pulled Successfully ✓` 或 `Uploaded Successfully ✓`：操作成功；
- `Sync Failed — Retry`：请求失败，可以修正配置后重试；
- `Resolve Sync Conflict`：首次同步或并发修改需要用户选择。

同步过程中按钮和 WebDAV 输入框会暂时禁用，防止重复点击或请求过程中改变端点。按钮下方会持续显示详细状态和最近一次成功同步时间；错误或冲突不会自动关闭设置面板。

脚本会在需要时递归创建缺少的父目录，并在同级创建 `backups/` 目录。

## 7. 建议的多端使用方式

完成首次 **Save and Check Now** 并建立同步基线后，正常情况下无需手动刷新或先拉取：

- Chrome 完成修改约 2 秒后自动上传；
- 切到 Safari 时，窗口聚焦或标签页重新可见会立即检查；
- Safari 检测到远端更新后自动拉取；
- 两台设备都开机但只操作其中一台，不会产生额外写入。

仍建议避免两台设备在数秒内同时修改同一文件夹结构。即使发生，条件请求也会阻止静默覆盖并进入冲突处理。

## 8. 性能与网络开销

脚本的后台开销主要受以下措施控制：

- 页面隐藏时不轮询；
- 最短检查间隔为 5 秒，避免 `focus` 与 `visibilitychange` 连续触发重复请求；
- 页面可见时只每 30 秒检查一次；
- 优先发送不下载正文的 `HEAD` 或小型 `PROPFIND`；
- 有版本标识时只在文件真正变化后执行 `GET`；完全没有版本标识时，前台轮询最多每 5 分钟执行一次 `GET`；
- 本地修改使用 2 秒防抖；
- 相同内容不重复上传；
- 每日备份和清理每天最多运行一次。

对于通常只有几 KB 到几十 KB 的文件夹配置，浏览器 CPU、内存和网络影响应当很低。

## 9. 兼容与迁移

- 继续使用原存储键 `nc_folder_config_v9`，旧的文件夹结构和 WebDAV 设置不会因为升级而主动丢失；
- 可以读取 V10 上传的完整配置格式；
- V11 上传的新格式只包含同步所需结构，字段为 `schemaVersion: 2` 和 `bases`；
- 原来的 `collapsed` 数据仍保存在每台设备本地，但不再写入云端；
- 脚本元数据增加了 `@connect *`，以允许用户配置任意 WebDAV 主机。油猴扩展首次访问新域名时可能要求授权。

## 10. 故障排查

### `Save and Check Now` 没有开始联网

确认：

- 已打开 **Enable WebDAV**；
- 已填写完整 JSON 文件 URL；
- 已实际点击 **Save and Check Now**；
- 按钮下方没有显示 URL 为空或认证失败。

仅打开开关不会联网，这是为了避免用户尚未填完 URL 和凭据时发出无效请求。

### 同步图标显示红点

点击图标查看具体状态：

- “冲突”：选择云端、本地或先导出；
- “错误”：检查 URL、凭据、网络和 WebDAV 权限；
- “待上传”：等待 2 秒，或手动点击“立即检查并同步”。

### 返回 401 或 403

检查：

- 用户名和密码；
- WebDAV 账户是否有读取、创建目录、写入和删除权限；
- Safari 油猴扩展是否允许脚本访问该 WebDAV 域名。

### 返回 405

某些服务不支持 `HEAD` 或部分 WebDAV 方法。脚本会自动尝试 `PROPFIND`。如果主同步可用但每日快照清理失败，可以保留现状并手动清理旧备份。

### 每日快照没有被清理

通常是服务不允许 `PROPFIND Depth: 1` 或 `DELETE`。这不影响主文件同步。可以在 WebDAV 服务端启用版本保留策略，或定期手动清理 `backups/`。

### 服务不返回 ETag

同步仍会工作，但冲突保护先退化为修改时间和文件大小；若这些信息也不存在，则使用上传前正文哈希复核。后者不是无竞态的条件写入，建议更换支持标准 ETag 与 `If-Match` 的 WebDAV 服务。

## 11. 安全说明

- WebDAV 凭据只保存在对应浏览器的用户脚本存储中；
- 凭据不会写入主同步文件、每日快照或导出的文件夹数据；
- Basic Auth 依赖 HTTPS 提供传输加密，因此 WebDAV URL 应使用 `https://`；
- 冲突和每日快照包含文件夹名称及表格 ID，应按需要设置 WebDAV 目录访问权限。
