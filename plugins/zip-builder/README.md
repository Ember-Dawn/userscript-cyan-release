# ZIP 打包器（ZIP Builder）

ZTools Windows 内置窗口插件：添加多个来源文件夹，展开目录树，单击整行选择文件或文件夹，单击箭头只展开/折叠。支持三态选择、局部手动排除、自动排除规则和按目录路径自动识别的选择方案。

## 使用

1. 点击「添加」选择一个或多个来源文件夹；需要替换或移除某个来源时，使用该来源根目录行尾操作。顶部「清空」移除所有当前来源，不删除磁盘文件。
2. 使用目录树勾选需要打包的内容。已保存过的同一路径会自动恢复匹配方案；也可通过顶部自绘方案菜单切换方案；底部固定提供保存修改和新建方案，方案条目右侧 `···` 可直接重命名或删除（无需先切换）。
3. 底部采用完整 ZIP 输出路径，默认 ZIP 名称由来源目录自动生成，可直接修改完整路径；来源变化时自动更新名称；底部不再提供刷新按钮。
4. 在右上角齿轮设置菜单中设置默认保存位置；底部可临时编辑完整路径。点击「生成 ZIP」，若目标文件已存在会弹出覆盖确认。
5. 可在齿轮设置菜单内设置排除规则，默认为 `.git`、`node_modules`、`__pycache__`、`.venv`、`.cache`。在树中手动重新勾选的文件/目录优先。

## 技术说明

- 插件入口 `plugin.json` 由仓库统一 Vite 构建；主窗口为 `dist/index.html`，Preload 为 `dist/preload.cjs`。无独立 BrowserWindow。
- 方案存在页面 `localStorage`（v2，兼容读取旧版 v1），按**当前来源目录的规范化绝对路径**匹配，单个目录可以保存多个命名方案。多来源打包时，方案只影响当前聚焦来源，其他来源的勾选不变。旧组合方案保留在存储中，但不进入目录专属菜单。
- 默认输出目录保存在本机 `localStorage`，与方案独立，不跨设备保证有效。
- ZIP 采用流式写入、ZIP64 结构和临时 `.part` 文件；损坏、取消、来源变化等错误会阻止提交。符号链接不跟随。
- 改动源码后运行 `node scripts/typecheck.mjs zip-builder`、`node scripts/build.mjs zip-builder`、`node scripts/check-icons.mjs zip-builder` 以及 `node tests/zip-builder.test.mjs`。
- 需要在 Windows + ZTools 实测 `showOpenDialog`、主窗口尺寸、菜单焦点、方案自动识别以及覆盖文件行为。

## 界面规范（v0.2.1）

- 使用 ZTools `removeSubInput()` 隐藏原生子搜索框，不操作宿主 DOM；插件进入时再尝试隐藏。
- 目录树紧凑行高 28px；整行可选择，箭头只展开。复选框状态使用本地 Lucide `check` / `minus`。
- 方案相关操作仅保留在方案菜单；更多菜单仅保留排除规则、默认保存目录及重置勾选。临时方案不再显示圆点。
- 排除规则采用无分隔线轻量列表；ZIP 主操作使用蓝色，其他背景保持 ZTools 灰黑中性色。

## v0.2.2 选择统计与图标

- 完全选中为蓝色，部分选中使用琥珀色描边及 Lucide `minus`，未选中为灰色空框。
- 文件夹、代码、文档、配置、压缩包及其他文件采用统一的 Lucide 图标与类型颜色；颜色不影响实际勾选状态。
- 底部自动统计已选文件数量及原始大小（不是压缩后大小），统计中显示已扫描量，完成后显示总量。
- 统计复用 ZIP 规划逻辑；选择变化延迟 300ms 扫描并取消过期扫描，结果按选择条件缓存 20 秒。压缩时仍会重新扫描、校验源文件。
- 目录特别大或存储较慢时，扫描可能持续一段时间；不需要展开所有子目录。

## v0.2.3 常用文件夹与目录方案

- 顶部新增常用文件夹自绘下拉框：只保存绝对路径，名称取末级目录名；列表按 `Intl.Collator('zh-CN',{numeric:true,sensitivity:'base'})` 自然升序。展开时名称为主、完整路径为副；重复名称以路径区分。
- 在当前来源下点击「收藏当前文件夹」收藏；点击常用项快速切换来源，取消收藏不会删除文件或方案。只有一个来源时切换会替换它；多来源时添加未加载的收藏来源并聚焦。
- 方案列表仅显示当前聚焦来源目录的方案。多来源时可点击来源行右侧「方案/当前」切换焦点；没有来源时方案不可用。保存、加载和重命名仅操作当前目录方案。
- 保留旧版 v2 方案数据，单来源方案继续可用；组合方案不自动套用到任何单个目录。
- 底部删除恢复自动命名按钮，来源变化时自动命名仍工作；手动输入的输出文件名保持优先。

### 清空工作区

顶部「清空」会清空当前全部来源目录与勾选，重置 ZIP 自动文件名、清除文件大小统计，不删除磁盘文件，也不影响常用文件夹、已保存方案及全局设置。若关联的已保存方案存在未保存选择修改，会先弹出确认。压缩期间不可清空。

## v0.2.5 操作栏优化

- 顶部不再显示「替换」按钮；保留来源根目录行尾的单独替换操作。
- 「清空」使用官方 Lucide `trash-2` 与柔和红色，清空范围和确认策略不变。
- 右上角使用官方 Lucide `settings`，下拉菜单项目只保留文字。
- 蓝色「生成 ZIP」按钮仅显示文字，不再显示图标。

## 方案与收藏下拉框（本轮更新）

- 方案下拉框不显示搜索框，使用有限高度的滚动列表；保存修改、新建方案固定在菜单底部，不随方案数量下移。
- 每个方案条目的 `···` 可展开针对该方案的重命名、删除操作；删除会确认且不会误删当前激活的其他方案。
- 常用文件夹右上角搜索图标按需展开名称或路径搜索，仍按中英文自然升序排列；每项可直接取消收藏，底部固定「收藏当前文件夹」。
- 菜单均为自绘组件；Esc 关闭，搜索输入不触发列表方向键导航。

## 重构后的维护结构

- `src/composables/useZipBuilder.ts` 统一协调来源、目录方案、收藏、扫描与压缩 UI 状态；组件通过同一个 Vue 上下文读取，不重复创建状态。
- `src/components/DirectoryTree.vue`、`PresetSelector.vue`、`FavoriteSelector.vue` 分别负责目录行和两个下拉菜单。`App.vue` 保留主布局和弹窗。
- `src/domain/preset-storage.ts` 负责 v1/v2 存储读取兼容、写入与已保存选择比较。方案快照中的旧 `rules` 字段保留兼容，但排除规则始终是全局设置，应用方案不会隐式覆盖。
- 压缩与后台统计共享 `planFiles`，一次扫描使用预编译的选择规则；ZIP64 写入逻辑保持不变。
- 除原有 ZIP 回归测试外，还可执行 `node tests/zip-builder-refactor.test.mjs` 验证存储兼容与选择规则一致性。

## 菜单轻量化

- 方案下拉菜单不显示统计标题或搜索框。每个方案右侧 `···` 打开不受列表滚动裁切的紧凑浮动菜单，仅提供重命名和删除。保存修改与新建方案为底部轻量文本操作。
- 常用文件夹下拉菜单不显示数量标题或右侧选中勾号；顶部右侧 Lucide 搜索按钮按需展开输入框，列表显示目录名称和完整路径，当前行以弱背景标记，右侧 `×` 可取消收藏。

## 菜单交互精修

- 方案下拉框取消选中勾号，以低对比度背景和“选中”文字标识当前方案；每个方案右侧直接提供重命名与删除图标按钮，不再展开 `···` 二级菜单。
- “保存修改”和“新建方案”在菜单底部同行展示。
- 常用文件夹搜索入口移至菜单底部，与“收藏当前文件夹”同一行；点击搜索后原位切换为输入框及关闭按钮，不再占据独立顶部行。

## 方案菜单内重命名

方案列表以弱背景表示当前项，不显示额外“选中”文字。点击对应方案右侧的铅笔图标在方案名称所在行直接切换为输入框，支持 Enter 保存、Esc 取消和同一来源内重名检查；不再弹出全屏重命名对话框。底部“保存修改”“新建方案”使用并列的轻量描边按钮。

- 方案重命名采用 Obsidian 式原位编辑：点击铅笔后名称在原行变为输入框，不新增行或弹窗；Enter 保存、Esc 取消，失焦时有效名称自动保存，非法名称不写入。


## 行内新建方案（最新版）

使用方案菜单底部「新建方案」会在列表顶部出现原位输入框并立即聚焦；Enter 保存、Esc 取消，失焦时有效名称保存，名称不能为空或与当前目录已有方案重名。「保存修改」直接保存当前方案，不弹出新建窗口；重命名仍在同一行完成。
